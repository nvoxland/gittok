# Stories row, notifications, offline, LAN (M5 contract)

## Stories row (SPEC §7.4)

`GET /api/stories` → `{"stories": [Story]}`, one per configured repo that has commits in the last 24 hours (wall clock), newest first:

```json
{"repo": "storefront", "mascot": "otter", "mascot_image": "/assets/mascots/otter.png?v=<mtime>" | null,
 "commits": [{"sha": "<full>", "short": "abc1234", "ts": 1700000000, "author": "Alice Archer", "subject": "Fix ...", "files": 3}],
 "seen": false}
```
- At most 10 commits per repo, from `git log --since=@<now-86400>` on the repo ref (via gitq), cached per repo head sha.
- `seen` is true when every commit sha was already viewed: `POST /api/stories/seen {"repo", "shas": [...]}` records them (table `story_views(repo, sha, seen_at)`).
- The web shows a horizontal row of circles (mascot image or initial) at the top of the feed; unseen repos get a colored ring. Tapping opens a full-screen story viewer: one commit per page (subject, author, time, files count, short sha), tap right/left to move, swipe down or ✕ to close; viewing marks shas seen.

## Notifications (SPEC §7.5)

Table `notifications(id, kind, text, card_id, created_at, read_at)` (exists). Generated by a server pass (in the learning worker loop, or its own worker) and `codescroll notify`:
- `new_cards`: "12 new cards from storefront" once per finished run with accepted > 0 (link: feed).
- `srs_due`: "2 quiz cards are back for another try" when due SRS cards exist and no unread `srs_due` notification exists. The dedup key is a hash of the sorted due card ids, so it fires once per distinct due set.
- `hot_file`: at most one per repo per UTC day, from the same commits used for stories. Files touched by ≥3 commits in the last 24 h count; paths under dot-directories (`.beads/`, `.claude/`) do not. One file gives "auth.py was in 3 commits in the last 24 hours"; several give a digest, "Busy day in storefront: brief.py (11 commits), cli.py (10), api.py (7) and 4 more". Deduplicated on (repo, date).
- `new_kind`: "A new Spot the Bug from billing/" when a card with story_type `spot_the_bug` lands (link: card). Only cards created in the last 24 hours count.
- Dedup key per notification so passes are idempotent.

`GET /api/notifications?unread=1` → `{"notifications": [{"id", "kind", "text", "card_id", "created_at", "read"}], "unread": n}`; `POST /api/notifications/read {"ids": [...]} | {"all": true}`. The web shows a bell with the unread count in the top bar and a `/notifications` list; tapping one with a card opens `/card/{id}`.

## PWA and offline (SPEC §11)

- `web/static/manifest.webmanifest` (name "CodeScroll", short_name, theme/background colors, `display: standalone`, icons 192/512 generated as PNG from an SVG at build time or committed), linked from `app.html` with `apple-touch-icon` and `theme-color` metas.
- A hand-written service worker (`web/static/sw.js`, registered from the layout when `'serviceWorker' in navigator`): precache the app shell (build assets list) and cache-first for `/assets/*` images; network-first with cache fallback for `GET /api/feed` (the last successful batch is served offline) and `/api/cards/*`; never cache `POST`s; queue `POST /api/events` while offline and replay on reconnect (Background Sync when available, else on next load).
- An "Offline — showing your last batch" banner when the feed came from cache.

## LAN access

- `codescroll serve --lan` binds `0.0.0.0` and prints the LAN URL(s) (first non-loopback IPv4 of each interface) next to the localhost URL.
- The feed is token-protected. `--lan` creates (or reuses) a random token in `<data_dir>/lan_token` (mode 0600) and prints a pairing URL per LAN address: `http://<lan-ip>:<port>/pair?t=<token>`. Opening it sets an HttpOnly, SameSite=Lax cookie `cs_lan` (long expiry) and redirects to `/`.
- Requests from non-loopback peers need the cookie, except `/pair`. Without it, `/api/*` returns 401 JSON and other paths return a small page that says to open the pairing URL. Loopback peers never need the cookie. The token is compared in constant time.
- MCP (`/mcp`) is loopback-only, always (not only with `--lan`). The server checks the peer address, not the Host header, and returns 403 to any non-loopback peer.
- Request bodies are limited to 1 MB (413). `POST /api/stories/seen` takes at most 100 shas, each 7-40 hex characters. `POST /api/events` takes at most 500 events, and each event `data` must be 4 KB or less as JSON.
- PWA install and offline mode need HTTPS: service workers do not register on plain-HTTP LAN origins. The feed still works in the browser over HTTP. Tailscale is the planned HTTPS path (M6).
- `settings.server.host` stays `127.0.0.1` by default; `--lan` is opt-in per run.
